**Langflow Assistant** is a chat panel beside the canvas that helps you make the parts of a flow you would otherwise write by hand.
You pick what you want in a tab above the message box:

* **Component**: Describe what a component should do, and **Langflow Assistant** writes a [custom component](/components-custom-components), checks it, and shows it on a card. Nothing reaches the canvas until you click **Approve**.
* **Prompt**: Describe how an **Agent** or a **Language Model** should behave, and **Langflow Assistant** writes its instructions. You apply them to the component with one click, or copy them.
* **Ask**: Ask how to do something in Langflow. **Langflow Assistant** answers from the documentation that ships with Langflow and never changes the canvas.

Next to the tabs, <Icon name="Play" aria-hidden="true"/> **Test flow** runs the flow on the canvas once and reports whether it works.

You build flows yourself, by adding and connecting components on the canvas.
**Langflow Assistant** doesn't add, connect, or remove components on its own.

Behind the scenes, **Langflow Assistant** runs its own agent on your Langflow server each time you send a message.
The agent has its own language model, separate from the models in your flow, and it only sees the flow that is open on the canvas.

## Prerequisites

* Connect an LLM provider in the [Global model providers page](/components-models) for **Langflow Assistant** to use.
* `LANGFLOW_AGENTIC_EXPERIENCE` must be `true` (default).

  **Langflow Assistant** is available out of the box. Set this to `false` to turn it off for a deployment, for example if you don't want model-generated component code running on your server.
  While it is off, the Assistant's endpoints return `404`.
  For more information, see [Supported environment variables](/environment-variables#supported-variables).

* The **Component** tab needs custom component creation to be enabled and permitted for your user role:
  * `LANGFLOW_ALLOW_CUSTOM_COMPONENTS` must be `true` (default).
  * `LANGFLOW_CUSTOM_COMPONENT_ADMIN_ONLY` must be `false` (default) for non-superusers. For superusers, this option is irrelevant.

  When you can't create custom components, the **Component** tab is turned off and its tooltip says why. The **Prompt** and **Ask** tabs keep working.
  For more information, see [Restrict custom component creation to superusers](/deployment-block-custom-components).

## Open Langflow Assistant

In the canvas toolbar, click the <Icon name="Langflow" aria-hidden="true"/> **Langflow** icon, or press <kbd>A</kbd>.

By default, the panel floats over the canvas and closes when you click outside it.
To keep it open while you work, click <Icon name="PanelRight" aria-hidden="true"/> **Dock to the side** in the panel header.
The docked panel sits to the right of the canvas, and the canvas shrinks to make room for it.
A docked panel stays open when you click the canvas or press <kbd>Esc</kbd>. To close it, click <Icon name="X" aria-hidden="true"/> **Close assistant**.
Drag the left edge of the docked panel to change its width.
Docking is available on screens at least 1024 pixels wide.

The panel remembers the last tab you used.
**Langflow Assistant** replies in the language you write in, and keeps component and field names in English so you can find them on the canvas.

## Create a custom component {#create-a-custom-component}

1. In **Langflow Assistant**, select the **Component** tab.
2. Describe what the component should do. For example:

    ```
    Create a component that hides email addresses and phone numbers in a text.
    ```

3. **Langflow Assistant** writes the component and checks it before showing it to you:

    * A security check rejects code that could harm the server, such as running shell commands, opening arbitrary files, or reading environment variables.
    * A structure check makes sure the code defines one component with valid inputs and outputs.
    * A name check makes sure the component doesn't take the name of a built-in component.
    * A test build creates the component and runs its outputs once.

    If a check fails, **Langflow Assistant** fixes the code and checks it again, up to three times.

4. The card shows the component's name, description, inputs, and outputs.
    To read the code, click **View code**.
    To add the component to the canvas, click **Approve**.
5. Connect the new component to the rest of your flow.

To change the component, keep writing in the **Component** tab, for example `Add an option to keep the last four digits of phone numbers`.
**Langflow Assistant** edits the component it wrote last in this session and keeps its name.
The updated component is added as a new component, so replace the old one on the canvas yourself.

Components that **Langflow Assistant** writes follow the same rules as [custom components you write yourself](/components-custom-components).
A component never reads files from the server's disk: to work with a file, connect a **Read File** component to the new component's input.
Every component is written so that you can also connect it to an **Agent** as a tool.

## Write instructions for an agent {#write-agent-instructions}

The **Prompt** tab writes the instructions of an **Agent** (its **Agent Instructions** field) or a **Language Model** (its **System Message** field).

1. Select the **Prompt** tab.
2. In **Apply to**, check which component the instructions are for.
    **Langflow Assistant** selects the component you selected on the canvas, or the first one that can take instructions.
3. Describe how the agent should behave. For example:

    ```
    Answer like a friendly support rep for an online store. Refunds are possible only within 7 days of purchase.
    ```

4. **Langflow Assistant** reads what the component is connected to, such as its tools, and writes instructions for it.
    The card shows the new instructions. To compare them with the current ones, click **Show current prompt**.
5. Click **Apply** to write the instructions into the component's field.
    To go back to the previous instructions, click **Undo**, or press <kbd>Ctrl</kbd>+<kbd>Z</kbd> (<kbd>Cmd</kbd>+<kbd>Z</kbd> on macOS) on the canvas.

To adjust the instructions, keep writing, for example `Make it shorter` or `Answer in bullet points`.
**Langflow Assistant** revises its last draft for the same component.

Sometimes the card only offers **Copy**:

* The canvas has no **Agent** or **Language Model** that can take instructions.
* The component's instructions field gets its value from a connection, for example from a **Prompt Template**. Writing into the field would have no effect, so copy the instructions to the component that feeds it.

In **Agent Instructions**, `{current_date}`, `{model_name}` and `{optional_user_context}` are filled in when the flow runs, and any other curly braces stay as typed.

## Ask questions {#ask-questions}

The **Ask** tab answers questions about Langflow and about the flow on the canvas, for example `How do I connect a file to the Agent?` or `What does this flow do?`.

**Ask** only reads. It can't add, connect, configure, or run anything, so the canvas stays editable while it answers.
If you ask it to build something, it tells you which tab to use or how to do it on the canvas.

Answers come from a copy of this documentation that ships with Langflow, so they match your Langflow version and don't need internet access.
Each answer ends with links to the pages it used.
To point those links at an internal mirror, set `LANGFLOW_ASSISTANT_DOCS_BASE_URL`.

To run **Ask** on a cheaper model than the other tabs, set `LANGFLOW_ASSISTANT_ASK_MODEL`.
For more information, see [Supported environment variables](/environment-variables#supported-variables).

## Test a flow {#test-a-flow}

To check the flow on the canvas, click <Icon name="Play" aria-hidden="true"/> **Test flow** next to the tabs.
**Langflow Assistant** saves the flow, runs it once, and shows the result on a card:

* **Test passed**: The flow ran without errors.
* **Test failed**: The flow stopped with an error. The card names the component that failed.
* **Needs your input to run**: The flow is set up correctly, but it needs something only you can provide, such as an API key, a file, or a database connection.

If the flow's **Chat Input** is empty, the test sends `Hello`.
A test doesn't use the Assistant's language model, and its messages don't appear in the **Playground**.

To see the error message, the test input, and the output, expand **Details**.
To run the test again, click **Test again**.
To chat with the flow yourself, click **Open Playground**. The **Playground** opens beside the canvas, and the panel stays usable.

## Reference canvas components in your messages

Reference components and their fields directly in a message using the `@` and `.` selectors.

In the message box, enter `@` to list the components on the canvas, and then select a component to insert its reference.
To select a specific field within a component, enter `.` after the component.
For example, in the **Ask** tab:

```
What should I put in @Agent.Language Model?
```

## Use a local or OpenAI-compatible model

**Langflow Assistant** can run on a model served from your own machine or from any OpenAI-compatible endpoint, so your messages never leave your environment.

To use a local model served by [Ollama](https://ollama.com), set the `OLLAMA_BASE_URL` global variable to your Ollama server, such as `http://localhost:11434`.
Ollama requires no API key.

To use an OpenAI-compatible server instead of OpenAI itself, set the `OPENAI_BASE_URL` global variable to your server's URL, and set `OPENAI_API_KEY` to the key your server expects.

You can set both values as [global variables](/configuration-global-variables) or as environment variables of the same name.
Global variables take precedence, and Langflow falls back to the environment variable when no global variable is set.

:::important
The **Component** and **Ask** tabs look things up with tools, so they need a model that supports tool calling.
Small local models often can't call tools reliably. If answers are vague or components keep failing their checks, try a larger model.
:::

## Connect an external client with MCP

Langflow's flow-authoring tools are available to external MCP clients, such as Cursor, Claude Code, and Codex, over a [streamable HTTP](https://modelcontextprotocol.io/docs/concepts/transports) MCP server at `/api/v1/agentic/mcp`.

This lets a client build, inspect, patch, and run your flows without opening the visual editor.
Changes are saved to your flows and appear in the visual editor.

The flow-authoring tools don't require `LANGFLOW_AGENTIC_EXPERIENCE`, because each one is a Langflow API call that your API key already authorizes.

Authenticate with a Langflow API key, in the same way as Langflow's other MCP endpoints:

```bash
curl -X POST "$LANGFLOW_URL/api/v1/agentic/mcp" \
  -H "x-api-key: $LANGFLOW_API_KEY" \
  -H "Content-Type: application/json"
```

For an MCP client, point it at `$LANGFLOW_URL/api/v1/agentic/mcp` with your API key as an `x-api-key` header.
Every tool call is authorized as your own user, so a client can only reach the flows your API key can reach.

For more information on creating an API key, see [API keys](/api-keys-and-authentication).
