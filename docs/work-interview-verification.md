# 업무 인터뷰 구현 및 검증

2026-09-22 · `feat/work-interview` · 시작점 `upstream/main`의 `5621dcfd84`

기존 작업 브랜치를 합치지 않고 별도 작업 디렉터리에서 구현했다. 새 플로우의 첫 화면은 쉬운 질문 다섯 개로 바뀐다. 반복 업무와 개인의 점검 순서·판단 기준을 모두 다룬다.

## 사용 흐름

1. 팀과 담당 업무, 함께 만들 일, 보는 자료, 처리 방법, 마지막 결과를 선택하거나 짧게 적는다.
2. 부족한 정보는 최대 두 번 더 묻는다. 답하기 어려우면 명시적으로 표시한 예시에서 시작한다.
3. 추천 업무를 고르고 그림의 단계를 눌러 내용을 확인한다. AI가 새로 쓴 기준은 확인해야 초안을 만들 수 있다.
4. 확인한 내용은 플로우에 저장한다. Assistant에는 짧은 한국어 요청을 보내고 서버가 저장된 업무 내용을 읽는다. 긴 답변도 기존 채팅 입력의 2,000자 제한 때문에 잘리지 않는다.
5. 생성된 초안을 기존 **Add to canvas** 버튼으로 적용한다. 업무 그림을 누르면 연결된 실제 구성 요소가 선택된다. 사람의 최종 검토는 수동 단계로 남는다.
6. **예시로 사용해보기**에서 자료를 넣고 직접 실행한다. 인터뷰 초안에는 기존 Assistant의 자동 실행 검증을 적용하지 않는다.

메일 자동 수신, 예약 실행, 사내 시스템 연결은 이번 범위에 포함하지 않는다. 후속 후보는 [AX 로드맵](ax-roadmap.md)에 기록했다.

## 실제 연결 검증

기존 환경 파일의 OpenAI 키로 인증을 확인했다. GPT-5.4로 인터뷰 추천, 내용 수정, 초안 생성, 적용, 설명 연결, 샘플 실행까지 확인했다. 기본 선택 모델 GPT-6-astra에서 발견한 temperature 호환성 문제를 수정하고 구조화된 인터뷰 응답도 확인했다. 키 값은 출력하거나 저장소에 추가하지 않았다.

품질팀의 일일 검사 보고를 예시로 사용했다. 사용자가 정한 기준은 불량률 2% 이상 표시, 수량 누락 시 계산하지 않기, 원문 한 건당 한 줄, 품목별 합치지 않기였다.

| 예시 입력 | 실제 결과 |
| --- | --- |
| 검사 1,000개, 불량 25개 | 2.5%, 확인 필요 |
| 검사 500개, 불량 5개 | 1.0% |
| 불량 3개, 검사 수량 미기재 | 자료 부족, 사람이 확인 |

결과에 사람의 최종 검토 안내와 원문 대조 목록도 포함됐다. 새로고침 후에도 인터뷰와 그림이 유지되고 실제 노드를 선택할 수 있었다.

## 검사 결과

| 검사 | 결과 |
| --- | --- |
| 인터뷰 API·서비스·입력 검증, 기존 Assistant 문맥·복구 회귀 | 48개 통과 |
| 인터뷰 UI·저장·추가 질문·늦은 응답 취소·화면 연결·기존 시작 창·상태 저장·오류 처리 | 119개 통과 |
| Vite 프로덕션 빌드 | 통과 |
| 변경 Python 파일 Ruff | 통과 |
| 변경 프런트엔드 파일 Biome | 오류 없음; 기존 PageComponent의 미사용 변수 경고 2개 |
| 전체 TypeScript 검사 | main과 작업 브랜치 모두 기존 오류 253개; 새 오류 없음 |
| 밝은 테마·어두운 테마·375px 화면 | 확인 |
| 키보드 초점, 답변 복원, 직접 만들기 종료 후 재진입 | 확인 |

TypeScript 비교는 같은 node_modules를 사용해 main의 프런트엔드를 별도 임시 디렉터리에서 검사했다. 전체 타입 검사가 통과한 상태는 아니다. 이 작업에 관련 없는 기존 오류는 수정하지 않았다.

모바일에서 업무 단계를 눌렀을 때 설명 패널이 노드를 가리던 문제도 수정했다. 375px 화면에서 패널이 접히고 선택한 노드가 x=27.5~347.5px 안에 표시됨을 확인했다.

독립 코드 검토에서 확인한 모델 호환성, 기준 출처 확인, 문자열·그래프 크기 제한, 모바일 노드 선택 문제를 수정하고 재검토했다.

## 로컬 실행

검증 환경은 프런트엔드 `http://127.0.0.1:3001`, 백엔드 `http://127.0.0.1:7861`이다. 기존 3000/7860 서비스와 별도 SQLite DB를 사용한다. `.runtime/`과 브라우저 검증 산출물은 로컬 제외 항목이며 커밋하지 않는다.

작업 디렉터리 루트에서 백엔드 실행:

```sh
mkdir -p .runtime
LANGFLOW_CONFIG_DIR="$PWD/.runtime" \
LANGFLOW_DATABASE_URL="sqlite:///$PWD/.runtime/interview.db" \
LANGFLOW_AUTO_LOGIN=true DO_NOT_TRACK=true \
uv run --no-sync uvicorn --factory langflow.main:create_app \
  --host 127.0.0.1 --port 7861 --loop asyncio \
  --env-file ../langflow_tuning/.env
```

별도 터미널에서 프런트엔드 실행:

```sh
cd src/frontend
VITE_PORT=3001 VITE_PROXY_TARGET=http://127.0.0.1:7861 \
  node_modules/.bin/vite --host 127.0.0.1
```

작업은 로컬 커밋으로 남겼으며 push와 merge는 하지 않았다.
